# v2 优化结果

2026-09-22。外部 Jev HTTP 协议不变；后端保持 DeepSeek Flash 非推理。

## 改动

1. 内部将客户端问题 ID 映射成稳定的 q0/q1，概率按显式选项键绑定，不再用无标签数组承载答案。
2. DeepSeek `/beta/chat/completions` 使用 `strict: true` 的 `submit_decisions` 工具调用；Schema 指定必填字段、禁止额外字段以及数字范围。运行时仍检查所有字段与概率总和，严格模式不是业务正确性的保证。
3. 通用提示词区分明确请求、引用、假设、撤销意图，独立评估各问题。
4. 保持概率总和容差 0.02，没有降低标准、补造遗漏概率或增加自动重试。
5. 记录失败校验原因，已解析的上游响应无论成功失败都记录 token 用量，不记录业务内容或密钥。

## 原始固定集对比

44 次请求 / 140 个判断，沿用原始输入和标签。旧版、Jev 和新版为不同时间的独立运行。

| 指标 | 旧版 | v2 最终严格调用版 | Jev |
|---|---:|---:|---:|
| 请求成功 | 30/44 (68.2%) | 42/44 (95.5%) | 44/44 |
| 成功响应内符合预期 | 86/100 (86.0%) | 133/134 (99.3%) | 139/140 |
| 全部计划判断的有效正确率 | 86/140 (61.4%) | 133/140 (95.0%) | 139/140 |
| 成功请求 P50 | 694.10 ms | 829.89 ms | 886.95 ms |
| 成功请求 P95 | 1110 ms | 1814.57 ms | 1072.67 ms |

仍有 2 次请求失败：repeat_3 的 score 选项字段数量不符；repeat_4 的 noul 类型或范围不符。
它们已被校验拒绝。不能声称启用 strict 后完全没有结构错误。

唯一成功返回但与预期不符的判断：question_refund 的部门分类，预期 billing，实际 sales。
255 选项案例通过，但耗时 5046.30 ms，仍不适合低延迟场景。

## 新增留出集

在新版首次评测前固定 12 次新请求 / 17 个判断。涵盖预订取消、否定、引用、假设、故障等级、库存、语言、嵌套状态、提示注入和信息不足。

12/12 请求成功，17/17 判断符合预期。P50 788.88 ms，P95 1289.79 ms。
评测后没有根据该集调整提示词。该集仍然是同一作者手工合成，规模小，不能作为独立真实业务基准。

## 用量和成本边界

新版原始集所有已解析上游响应：输入 56416 tokens，缓存命中 32640，输出 6064。
缓存输入占比 57.9%。成功请求输入 54528、缓存 31104、输出 5871。

旧版只记录成功调用，因此不作整轮成本比值比较。新版 Schema 和显式键带来了更多输入、输出；缓存比例变高并不自动意味着总成本更低。
此轮优先修复输出稳定性和语义质量，尚未达到成本/速度全面优于 Jev 的目标。

## 过程透明性

- v2-results.json 是仅使用键值 JSON 的中间版本：33/44 成功、106/107 判断符合预期；未拿其数据充当最终版本。
- v2-strict-probe-results.json 是严格调用单请求验证，不混入正式集统计。
- v2-strict-results.json 是最终原始集完整结果；v2-strict-holdout-results.json 是留出集结果。
- 各轮没有自动重试；失败保留在分母。阈值不变：Noul >=0.5，Score 四舍五入到最近等级，Choice 精确匹配。
- 并发设置不变：语义/边界并发 3，batch/repeat 串行。计时包含网络；不是纯模型推理时间，亦非同时对照试验。成功请求 P95 不包含失败请求。
- 概率校准未验证；合成集符合率不是通用准确率。

## 工程验证

Go 竞态测试、go vet、构建及官方 typesafe-sdk 0.7.1 模拟联调均通过。
核心 decision 包语句覆盖率 89.3%。新增测试验证键顺序不影响结果、缺失/未知/多余键拒绝，以及 Schema 每层 required/additionalProperties/数字范围。
